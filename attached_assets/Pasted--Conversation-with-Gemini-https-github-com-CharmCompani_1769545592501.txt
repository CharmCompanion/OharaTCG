To fix the UI overlap and scene navigation, we need to address the Control Node hierarchy and Signal routing. Since Godot’s containers automate sizing, your overlaps are likely caused by conflicting "Expand" flags or manual size overrides that fight the container.



1. Fixing the DeckEdit.tscn UI Overlap

For the top row where the Deck Name dropdown is overlapping, ensure the following settings in the Inspector for your HBoxContainer children:



Deck Name DropDown (OptionButton):



Horizontal Sizing: Set to Fill but uncheck Expand.



Custom Minimum Size: Set a specific x value (e.g., 200px) to prevent it from collapsing, but don't use size directly.



Spacing Fix: * Check the HBoxContainer properties: Under Theme Overrides > Constants, set Separation to your desired gap (e.g., 10px).



Ensure all other buttons in that row are set to Horizontal: Shrink Begin or Center so they don't fight the dropdown for space.



2. Making Top Buttons Work (Input Blocking)

If your buttons don't click, another Control node is likely "eating" the mouse events.



The Fix: Check every parent node of your buttons (especially Panel, MarginContainer, or transparent Control nodes). Set their Mouse > Filter to Pass or Ignore. Only the Button itself should be set to Stop.



Debugging Trick: While the game is running, go to the Debugger tab > Misc and look at "Clicked Control". It will tell you exactly which node is blocking your button.

Select the main background Panel or ColorRect.



Mouse > Filter: Set to "Ignore". If this is set to "Stop", none of your buttons will ever work.



Why the buttons weren't working:

In Godot, if a TextureRect or a Panel is higher in the scene tree hierarchy (or lower on the list) and has Mouse Filter set to Stop, it acts like an invisible pane of glass over your buttons. Setting them to Ignore or Pass is the most common fix.
